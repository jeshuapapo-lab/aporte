# Guía docente · Integraciones rentables de software y hardware

Objetivo: Diseñar una integración rentable de hardware y software con interoperabilidad, pruebas de datos y evaluación de costo total.

## Orientación del caso

180−60=120 dólares netos al mes; 1200/120=10 meses de recuperación simple. Probar identidad, operación única, actualización de existencias, confirmación y reintento tras caída; declarar que no se descontaron flujos ni se garantizó el ahorro.

## Conceptos y evidencias

### Integración con propósito
Integrar hardware y software conecta eventos físicos y registros digitales. Un lector puede capturar un código, una aplicación validar el producto y un sistema actualizar existencias. La rentabilidad depende del problema resuelto, el volumen y el costo total. Comprar dispositivos sin revisar el proceso puede acelerar la captura de información equivocada en lugar de reducir errores.

### Interfaces e identificadores
Define qué datos produce cada dispositivo, qué formato usa y quién los interpreta. Un código debe corresponder a un identificador único y vigente en el catálogo. Las interfaces y controladores necesitan compatibilidad comprobada. Diferencia la lectura del código de la validación de la transacción: que un lector emita una señal no demuestra que el inventario haya cambiado correctamente.

### Errores y continuidad
La integración debe manejar lecturas repetidas, códigos desconocidos, conexión interrumpida y reintentos. Decide cuándo una operación se considera confirmada y cómo se evita contabilizar dos veces el mismo evento. Incluye permisos, respaldo y trazabilidad. Una operación sin conexión requiere reglas de sincronización y resolución de conflictos, no solamente almacenar datos hasta que vuelva internet.

### Economía y prueba piloto
Calcula adquisición, instalación, licencias, capacitación, soporte y reposición. Compara ahorro neto esperado con inversión y analiza sensibilidad al volumen. Un piloto debe probar tareas normales y fallos representativos, midiendo tiempo y errores antes y después. La recuperación simple de la inversión orienta, pero no refleja por sí sola el valor temporal ni todos los riesgos del proyecto.
